# 知序 · 科研助手

一个本地运行的科研文献工作台。支持真实 PDF 入库、扫描件 OCR、版本比较、原文阅读、带页码和坐标的证据检索，以及可配置模型的问答、翻译和写作。会话、笔记、阅读位置和后台任务保存在本地 SQLite 中。

## 快速开始

需要 Python 3.12 和 Node.js 20.19+。如果已安装 uv，启动脚本也可通过它准备 Python 3.12。首次安装需要网络。锁定 Python 3.12 是为了同时满足 NumPy 和 OCR 引擎的版本要求。

```bash
bash scripts/start.sh
```

打开 **http://127.0.0.1:8000**。在文献库点击“导入样例”可从项目的 `pdf/` 目录选择真实论文。也可以直接拖入 PDF，支持批量上传。

停止后再次运行同一命令即可继续使用。数据保存在被 Git 忽略的 `data/` 中：SQLite 数据库、上传文件副本、翻译缓存和任务状态。升级会自动补充数据库表和列；原始 `pdf/` 测试资料不会被修改或删除。解析器升级后，文献库会显示“可更新解析”；在更多操作中选择“从首页重建解析”即可更新派生文本，保留原 PDF、文献 ID、自定义信息和研究记录。

### 配置模型

在应用的“模型设置”填写兼容 `chat/completions` 的服务地址、模型名称、API 密钥，然后测试连接。也可以复制 `.env.example` 为 `.env` 后设置环境变量。界面保存的配置优先于环境变量。

- 未配置模型：上传、OCR、阅读、检索原文、引用图谱和 CSV 绘图均可使用；问答明确显示 **BM25 检索摘录模式**。
- 配置模型后：启用基于证据的回答、页/段落、划词、句段对照及全文翻译、文献综述、研究方向和写作提纲。
- 密钥只在本地后端保存，设置接口不会返回密钥。界面保存的配置文件权限为 `0600`。请求模型时，所选证据或待翻译内容会发给你配置的模型服务。
- 密钥绑定服务地址；更换地址时填写新密钥，留空会清除旧密钥。同址切换模型可保留密钥。“清除密钥”可回到检索摘录模式，重启也不会恢复环境变量中的旧密钥。
- 本地兼容模型服务可填写 `http://127.0.0.1:端口/v1`；若服务不要求密钥，可填本地服务接受的占位值。

## 技术结构

```text
frontend/              React + TypeScript + Vite 工作台
backend/app.py         FastAPI 接口、输入校验、静态前端
backend/documents.py   PDF 解析、OCR、原文页面渲染
backend/storage.py     SQLite 持久化、文件与版本、块/翻译/任务
backend/tasks.py       本地任务执行与页级恢复
backend/intelligence.py BM25、模型调用、arXiv
backend/answer_validation.py 局部引用、数字/单位与实验关系风险提示
backend/answer_contract.py 逐条问答格式、原文降级与完整草稿保留
backend/citations.py   参考文献匹配与带来源的局部图谱
backend/translation_routes.py 原文句段编号配对、缓存和对照导出
backend/charts.py      从 CSV 确定性生成图表
backend/workspace_routes.py 会话、笔记、阅读记录和任务控制
backend/document_routes.py 搜索、参考文献导航、版本差异和导出
backend/request_control.py HTTP 断开时取消本地上游请求
backend/backup.py      一致快照备份、校验与安全恢复
scripts/              启动、备份、检索评测、压力测试和浏览器回归
docs/API.md           前后端接口
tests/                接口与持久化集成测试
```

检索片段保留 `paper_id / page / block_id / bbox`。问答限定已选版本；默认全库检索取每个论文家族最新的可用版本。不同版本的 PDF 和已经返回的来源不会被静默覆盖。

本地初版选择 SQLite 和线程任务执行器以减少安装要求；使用单个 Uvicorn worker。文献量、并发增长后可替换成 PostgreSQL/pgvector 和独立队列，不需要更改前端交互。

## 备份与恢复

备份包含 SQLite 一致快照、文献副本、会话、笔记历史、阅读位置、翻译缓存和任务检查点。每个文件都有 SHA256 校验。模型设置和密钥不进入备份，恢复后需要重新配置。可在应用运行时备份；遇到文献正在删除或变更会失败并提示重试，不发布不完整的备份包。

```bash
mkdir -p backups
.venv/bin/python scripts/backup.py create --data data --output backups/workspace.zip
.venv/bin/python scripts/backup.py verify backups/workspace.zip
.venv/bin/python scripts/backup.py restore backups/workspace.zip --target restored-workspace
```

输出文件必须是新文件；恢复目标必须是新目录或空目录，不能覆盖当前 `data/`。请另行保存创建结果中的 `archive_sha256`，以后可在 `verify` 或 `restore` 中加 `--sha256 摘要` 校验整个备份包。备份包内有文献和研究内容，请自行妥善保存。

恢复会重写文献路径，并暂停原先未结束的任务，防止启动后自动调用模型。确认恢复结果后可使用 `RESEARCH_DATA_DIR="$PWD/restored-workspace" bash scripts/start.sh` 启动恢复的工作区；请先停止占用 8000 端口的旧实例。备份只读取源业务数据，SQLite 可能维护自己的 WAL/SHM 辅助文件。

完整检查运行后端测试、前端测试、生产构建和真实 PDF 检索验收，报告写入 `test-results/retrieval.json`。第一次离线评测会解析扫描件，后续复用带源文件与解析器哈希的缓存；不调用模型服务，不修改应用文献。缺失 PDF、失效的标准证据或检索未命中会使评测失败。

`--all` 还会运行以下检查，某一步失败后仍会完成其余检查，最终返回非零退出码：

- **真实浏览器回归**：Playwright 启动独立端口和临时数据库，覆盖上传、解析、问答、笔记、阅读和移动端等流程。服务使用真实后端，测试完成后清理临时数据。报告和失败截图/trace 位于 `frontend/test-results/e2e/`。单独运行：`npm --prefix frontend run test:e2e`。
- **导入压力测试**：合成原生文字 PDF，真实执行批量上传、后台解析、并发去重、阅读和检索，再检查数据库、文件哈希和来源定位。报告为 `test-results/import-stress.json`。可单独运行 `.venv/bin/python scripts/stress_import.py --papers 120 --pages 6 --concurrency 8`。这是本机合成负载，不代表扫描 OCR 或公网并发容量。
- **进程与故障回归**：后端测试包含真实隔离进程强制退出、HTTP 断线、数据库提交失败和本地模型 HTTP 429/503。仅结束测试自己启动的进程，验证已提交结果保留、未提交事务回滚、重试及检查点恢复；不调用外部模型。未落盘的上游请求在重启后可能重复发送。
- **重复启动保护**：同一数据目录由一个运行中的应用持有系统文件锁。第二实例立即提示关闭旧实例或更换数据目录，不执行恢复或清理；正常退出会等待后台写入结束，进程异常退出后锁由操作系统释放。锁文件保留在目录内，无需手工删除。

`.github/workflows/check.yml` 提供 GitHub Actions 检查：Python 3.12、Node 22、后端/前端测试、Chromium/Firefox/WebKit、完整扫描 OCR、压力测试和四套已知 PDF 开发评测。使用只读仓库权限，不需要模型密钥；上传测试报告供查错。项目需放入 GitHub 仓库并启用 Actions 后才会在云端运行。语料评测要求 `pdf/` 中的对应论文及哈希完整，缺文件会失败，不会当作通过。

全文翻译的 token 数量是工作量估计，实际用量由模型服务决定。暂停/取消在安全检查点生效；当前已提交给服务方的调用可能继续消耗用量。已经返回并保存的文本块会在恢复时复用。会话和笔记采用版本检查，冲突返回 409，不静默覆盖其他窗口的内容。

## 当前边界

- 这是**本地单用户初版**，默认仅监听本机回环地址；尚未实现多用户登录、租户隔离和公网部署。
- 当前使用真实 BM25 检索，尚未接入向量模型、重排模型或复杂 Agent 编排。模型能力取决于用户配置的服务。
- 解析为 PyMuPDF/OCR 基线，尚未接入 Docling/GROBID。复杂公式、跨页表格、机构脚注对应和扫描件顺序可能需要人工核查，原始页面始终可查看。
- 句段对照按原文字符范围与固定编号绑定译文，两侧可定位到同一原文块；这不等于自动验证译文语义正确。公式/表格保留块结构，过长内容提示使用整页翻译；未实现原位中文 PDF 重排。OCR 文字层的位置为估计值。
- 引用图谱展示导入集合内的匹配关系，可能漏边；不代表整个研究领域影响力。研究方向不保证原创或从未被尝试。
- arXiv 搜索需要可用网络。自动定时推荐、协同过滤、跨站全文抓取和自主执行生成代码尚未实现。
- 已从 OpenAI 官方来源补齐 GPT-2 原论文，来源与 SHA256 记录在 `tests/fixtures/corpus_provenance.json`；新工作区可通过“导入样例”选择它。完整 GPT-1/2/3 对比的回答质量仍需单独进行真实模型验收。
- 每份上传限制 100 MB，扫描 OCR 对 CPU 有一定开销。首次 OCR 加载模型较慢，后续页复用引擎。

模型、解析库及字体等依赖各自适用其许可证；发布或分发时请保留相应许可文件。

## 首轮真实模型小样本验收（4 次）

用户明确授权后，向已配置的 DeepSeek `deepseek-flash` 发送 4 次请求：两道基于论文的问答、同一段落的普通翻译与句段配对。请求与预览逐条校验，接口结构检查 4/4 通过。预览和原始结果在 `test-results/model-request-preview.json`、`test-results/model-integration.json`，没有密钥。

AI 对照原文复核：两道主问题的核心答案均有支持，测试段落及两段配对译文保留了关键含义。但 DeepSeek-V3 回答主动补充的基线实验解释混用了不同实验的引用，只能判为部分支持；不能宣称整份回答已通过语义验收。详见 `test-results/model-integration-review.json`。这 4 次调用不代表总体质量、专业验收或完整 GPT-1/2/3 对比质量；未采集服务方实际 token 用量和费用。

## 引用质量改进

回答提示词现在要求直接回答问题、逐项就近标注来源，并把数量与实验、表头、配置和版本绑定；不根据其他实验的相似数字补齐归属。`backend/answer_validation.py` 按局部引用检查 B/M/T/K、单位、逐字引句与跨来源拼接，给出最多 3 条具体风险提示，显示并保存到会话。组合引用支持 `[1,2]`；引句或代码中的论文原编号不会被误当成本次来源编号。

规则始终返回 `semantic_entailment_verified:false`，不会据此宣称语义正确或擅自删除回答。旧真实回答可在本地重放检查，报告为 `test-results/model-v3-recorded-response-review.json`，不产生新 API 调用。引用图谱也会拆开无稳定标识且作者冲突的同名论文族，避免已匹配到 A 却跳转到 B。

新增真实模型验收可用 `scripts/verify_model.py --answers-only --preview --output 预览路径` 准备仅两道问答；获准后用同样的 `--answers-only` 和 `--approved-preview 预览路径` 发送。脚本逐条校验目标和消息，发生变化就停止该请求；翻译不包含在此模式中。
